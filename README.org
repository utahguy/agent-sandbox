#+TITLE: agent-sandbox
#+DESCRIPTION: Run AI coding agents in isolated OCI containers — Bash CLI + Python library

* Overview

~agent-sandbox~ runs AI coding agents inside rootless containers with
full filesystem access to your project.  It handles authentication,
git/SSH/GitHub CLI config, and per-project toolchain management
automatically.

Available as:
- *Bash CLI* — =agent-sandbox= script for interactive use
- *Python library* — =pip install agent-sandbox= for programmatic
  use (e.g. from AEF or other automation frameworks)

Supported agents:
- *Claude Code* (default) — Anthropic's coding agent
- *Codex* — OpenAI's coding agent
- *Aider* — Open-source AI pair programming tool

Supported runtimes:
- *Podman* (rootless) — default
- *Docker* — auto-detected when Podman is not available

* Prerequisites

- [[https://podman.io/][Podman]] (rootless) or [[https://docs.docker.com/][Docker]] — the container runtime
- An active subscription or API key for at least one agent:
  - Claude Code: Claude Pro/Max subscription (OAuth login)
  - Codex: ChatGPT Plus/Pro subscription (OAuth login)
  - Aider: API key for Anthropic or OpenAI

* Installation

** Bash CLI (interactive use)

Clone the repo and symlink the script onto your PATH:

#+begin_src bash
git clone https://github.com/utahguy/agent-sandbox.git
ln -s "$(pwd)/agent-sandbox/agent-sandbox" ~/.local/bin/agent-sandbox
#+end_src

Create the config directory for per-agent env files:

#+begin_src bash
mkdir -p ~/.config/agent-sandbox
#+end_src

The container image builds automatically on first run.

** Python library (programmatic use)

#+begin_src bash
pip install agent-sandbox
#+end_src

Or install from source:

#+begin_src bash
cd agent-sandbox
pip install -e .
#+end_src

* Python Library API

The library provides a typed, testable API for container
orchestration.  It follows Clean Architecture with domain entities,
application use cases, and infrastructure adapters.

** Quick start

#+begin_src python
from agent_sandbox import Sandbox, SandboxConfig

# Load config from .agent-sandbox file
config = SandboxConfig.from_file(".agent-sandbox")

# Or build programmatically
config = SandboxConfig(
    volumes=[Volume("/host/project", "/workspace", mode="rw")],
    ports=[PortMapping(host_port=5555, container_port=5555)],
    mise=True,
    memory_limit=MemoryLimit.of("8g"),
    runtime=RuntimeKind.AUTO,
)

# Use as context manager
with Sandbox(config) as container:
    result = container.exec("yarn test", timeout=300)
    print(result.exit_code, result.stdout)
#+end_src

** Key classes

| Class            | Module                         | Purpose                                  |
|------------------+--------------------------------+------------------------------------------|
| =Sandbox=        | =agent_sandbox.facade=         | Public API — start/stop/exec             |
| =SandboxConfig=  | =agent_sandbox.domain.entities= | Typed config (volumes, ports, env, mise) |
| =Volume=         | =agent_sandbox.domain.value_objects= | Host-to-container volume mount     |
| =PortMapping=    | =agent_sandbox.domain.value_objects= | Host-to-container port mapping     |
| =MemoryLimit=    | =agent_sandbox.domain.value_objects= | Container memory limit             |
| =RuntimeKind=    | =agent_sandbox.domain.value_objects= | AUTO, DOCKER, or PODMAN            |
| =SandboxError=   | =agent_sandbox.exceptions=     | Base exception with error codes          |

** Architecture

#+begin_src text
agent_sandbox/
  domain/           Pure entities and value objects (zero framework imports)
    entities.py      SandboxConfig, ContainerHandle, ExecResult
    value_objects.py  Volume, PortMapping, MemoryLimit, RuntimeKind
    image_spec.py     Container image specification
  application/       Use cases and port interfaces
    ports.py          ContainerPort, ConfigSourcePort, RuntimeDetectorPort
    use_cases/
      parse_config.py     Parse .agent-sandbox files
      detect_runtime.py   Auto-detect Docker vs Podman
      ensure_image.py     Build/pull container image
      start_sandbox.py    Start a container
      stop_sandbox.py     Stop a container
      execute_command.py  Run commands inside container
      run_agent.py        Run an AI agent (Claude/Codex/Aider)
  infrastructure/    Concrete adapters
    container_adapter.py   Docker/Podman container lifecycle
    file_config_source.py  .agent-sandbox file parser
    image_builder.py       Container image builder
    subprocess_runtime.py  Runtime detection via subprocess
  facade.py          Public Sandbox API (context manager)
  cli/main.py        CLI entry point
  exceptions.py      Typed exception hierarchy with error codes
#+end_src

* Bash CLI Usage

** Basic usage

#+begin_src bash
# Claude Code (default agent) in current directory
agent-sandbox

# Specify a project directory
agent-sandbox /path/to/project

# Pass arguments to the agent
agent-sandbox -- -p "fix the failing tests"
#+end_src

** Selecting an agent

#+begin_src bash
agent-sandbox --agent claude .     # Claude Code (default)
agent-sandbox --agent codex .      # OpenAI Codex
agent-sandbox --agent aider .      # Aider
#+end_src

** Running as a different user

For service accounts or multi-user setups:

#+begin_src bash
agent-sandbox --as arm /home/arm/project
agent-sandbox --as arm              # defaults to that user's home dir
#+end_src

Requires sudo access to the target user.  Enables systemd lingering
automatically for rootless Podman.

* Authentication

** Claude Code

Authenticate on the host first:

#+begin_src bash
claude login
#+end_src

Auth tokens (~.claude.json~, ~.credentials.json~) are mounted
read-write into the container so token refreshes persist.

*** Multiple accounts

If you work with multiple clients, each with their own Claude
subscription, keep a separate config directory per account:

#+begin_src bash
CLAUDE_CONFIG_DIR=~/.claude-client-acme claude login   # first time only
CLAUDE_CONFIG_DIR=~/.claude-client-beta claude login   # first time only
#+end_src

Then point each project at the right account via its ~.agent-sandbox~:

#+begin_src conf
claude-config: ~/.claude-client-acme
#+end_src

Credentials from that directory are mounted read-write (so token
refreshes persist) and settings files read-only, exactly like the
default auth flow.  The host's default =~/.claude= is ignored when
=claude-config= is set.

** Codex

The ~.codex/~ directory is mounted read-write.  On first run, Codex
will prompt you to log in inside the container.  The login persists
across sessions.

Codex requires Node.js.  Add a ~.mise.toml~ to your project:

#+begin_src toml
[tools]
node = "22"
#+end_src

** Aider

Aider authenticates via API keys.  Create an env file:

#+begin_src bash
echo "ANTHROPIC_API_KEY=sk-ant-..." > ~/.config/agent-sandbox/aider.env
#+end_src

Aider requires Python.  Add a ~.mise.toml~ to your project:

#+begin_src toml
[tools]
python = "3.12"
#+end_src

* Per-Agent Environment Files

Any agent can receive extra environment variables via
=~/.config/agent-sandbox/<agent>.env=.  Each line is =KEY=VALUE=,
comments start with =#=:

#+begin_src conf
# ~/.config/agent-sandbox/aider.env
ANTHROPIC_API_KEY=sk-ant-...
#+end_src

* Toolchain Management with mise

The container includes [[https://mise.jdx.dev/][mise]] for managing
language runtimes (Python, Node.js, Rust, Go, etc.).  Drop a
~.mise.toml~ in your project root:

#+begin_src toml
[tools]
python = "3.12"
node = "22"
rust = "1.82"

# npm packages are also supported
"npm:android-mcp-server" = "latest"
#+end_src

The entrypoint runs ~mise install~ automatically at container start.
Installed toolchains are cached on the host at
=~/.local/share/agent-sandbox-mise/= and shared across all projects.

Mise also reads idiomatic version files: ~.python-version~,
~.node-version~, ~.nvmrc~, ~.ruby-version~, ~.go-version~,
~.tool-versions~.

* Per-Project Configuration

Create a ~.agent-sandbox~ file in your project root for extra volume
mounts, port mappings, and environment variables:

#+begin_src conf
# Extra volume mounts (podman -v syntax)
volume: /host/data:/home/claude/data:ro,Z
volume: ~/shared-models:/models:ro,Z

# Port mappings
port: 3000
port: 8080:80
port: 5555:5555    # ADB for Android emulator access

# Environment variables
env: SLACK_WEBHOOK_URL=https://hooks.slack.com/services/T.../B.../xxx
env: API_BASE_URL=https://api.example.com

# Mise toolchain management
mise: true

# Container resource limits
memory: 8g

# Container runtime (auto-detected if omitted)
runtime: auto

# Claude account to use (default: ~/.claude)
claude-config: ~/.claude-client-acme
#+end_src

Supported directives:

| Directive      | Format                          | Purpose                                      |
|----------------+---------------------------------+----------------------------------------------|
| =volume=       | =HOST:CONTAINER[:mode]=         | Extra bind mount (=ro= or =rw=, default =rw=) |
| =port=         | =HOST[:CONTAINER[/proto]]=      | Port mapping (default proto: =tcp=)          |
| =env=          | =KEY=VALUE=                     | Container environment variable               |
| =mise=         | (no value)                      | Enable mise toolchain install at startup     |
| =memory=       | =<integer><unit>= (b/k/m/g)    | Container memory limit                       |
| =runtime=      | =auto= / =docker= / =podman=   | Override container runtime                   |
| =packages=     | =PACKAGE_NAME=                  | apt package to install at startup            |
| =claude-config= | =PATH=                         | Host Claude config dir for account selection |

For backwards compatibility, ~.claude-sandbox~ is also recognized.

* MCP Server Integration

To make MCP servers available to Claude Code inside the container,
add a ~.mcp.json~ to your project root:

#+begin_src json
{
  "mcpServers": {
    "android": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "android-mcp-server"],
      "env": {
        "ANDROID_HOME": "${ANDROID_HOME:-$HOME/.android/sdk}"
      }
    }
  }
}
#+end_src

Combined with ~.mise.toml~ (to install the MCP server) and
~.agent-sandbox~ (to map the ADB port), this enables autonomous
mobile device testing from inside the container.

* What Gets Mounted

| Resource           | Mount mode | Notes                                      |
|--------------------+------------+--------------------------------------------|
| Project directory  | read-write | Mounted at =/workspace=                    |
| Git config         | read-only  | =~/.gitconfig=, =~/.gitignore_global=     |
| SSH keys           | read-only  | Symlinked; =known_hosts= copied writable   |
| SSH agent socket   | read-write | Forwarded via =$SSH_AUTH_SOCK=             |
| GitHub CLI config  | read-only  | Copied writable at startup                 |
| Claude auth tokens | read-write | From =~/.claude= or =claude-config= dir   |
| Codex auth         | read-write | Login persists to host                     |
| Claude sessions    | read-write | Stored in =PROJECT/.claude-sessions/=      |
| Mise cache         | read-write | Shared at =~/.local/share/agent-sandbox-mise/= |
| uv cache           | read-write | Host cache directory                       |

* Tips

** Injecting context into the agent

Each agent reads its own convention-named file from the project root:

- *Claude Code* reads =CLAUDE.md=
- *Codex* reads =AGENTS.md=
- *Aider* reads =CONVENTIONS.md= (via =--read=)

** Slack notifications when Claude finishes thinking

Claude Code fires a =Notification= hook each time it finishes a
response.  Set the webhook URL in your project's =.agent-sandbox=:

#+begin_src conf
env: SLACK_WEBHOOK_URL=https://hooks.slack.com/services/T.../B.../xxx
#+end_src

Then add a =Notification= hook to your Claude Code settings:

#+begin_src json
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "curl -s -X POST -H 'Content-type: application/json' --data '{\"text\":\"Claude finished thinking\"}' \"$SLACK_WEBHOOK_URL\"",
            "async": true
          }
        ]
      }
    ]
  }
}
#+end_src

* Troubleshooting

** =can't raise ambient capability CAP_*= during image build

These come from rootless Buildah/crun during =RUN= steps.  The build
completes successfully — the warnings are cosmetic.

To silence: =export BUILDAH_ISOLATION=chroot= or upgrade =crun=.

** =Executing external compose provider "...docker-compose"=

Benign — Podman delegating to docker-compose.  Silence with:

#+begin_src toml
# ~/.config/containers/containers.conf
[engine]
compose_warning_logs = false
#+end_src

* Rebuilding the Image

The image rebuilds automatically when ~Containerfile~ or
~entrypoint.sh~ change.  To force a rebuild:

#+begin_src bash
podman rmi agent-sandbox-$(id -u)
agent-sandbox
#+end_src
